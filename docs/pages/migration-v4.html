MCP Probe Kit v3 → v4

v4 保留主要工具能力，同时收敛默认模型工具面，升级双协议、计划恢复、Memory 生命周期与正式 MCP Apps。

24 默认 / 30 Memory / 34 full Node.js 20+ Legacy + Modern MCP Apps

RC 安装

候选版本使用 npm next 标签，不覆盖稳定版 latest。

# MCP 客户端：使用稳定 v4
npx -y mcp-probe-kit@4.0.0

# 项目内 Agent fallback：精确锁定版本
npx -y mcp-probe-kit@4.0.0-rc.10 install-agent

# 临时运行精确版本
npx -y mcp-probe-kit@4.0.0-rc.10

工具面变化

配置模型可见用途
默认 / compact24推荐日常使用
compact + Memory30增加 6 个 Memory 工具
MCP_TOOLSET=full34兼容与诊断

add_feature、fix_bug、sync_ui_data、ask_user 不再进入默认模型工具面，但能力仍由编排、脚本或 full 模式保留。

正式 MCP Apps

客户端协商 io.modelcontextprotocol/ui 且支持 text/html;profile=mcp-app 后，服务端提供五个交互界面：

  • Memory Center
  • Feature Workbench
  • Bug Workbench
  • Product Workbench
  • Convergence Gate
打开五个真实动态演示 →

list_memory_assets 标记为 App-only，不计入 24/30 个模型可见工具。未支持 GUI 的客户端继续使用文本和结构化结果。

# 显式关闭 MCP Apps
MCP_ENABLE_UI_APPS=0

协议模式

模式行为
auto默认，自动协商 Legacy 或 Modern。
legacy固定旧协议，用于兼容诊断。
modern拒绝 Legacy opening，用于 Modern 验证。
 
MCP_PROTOCOL_MODE=auto

计划恢复与 Memory 写入

start_*
→ plan_heartbeat
→ Agent 执行实现与测试
→ resume_plan（中断后）
→ converge
→ memorize_asset（仅在通过后）

检查点保存在项目内 .mcp-probe-kit/plans/。只有 converge passed=true 后才能写入正式长期记忆。

验证与回退

npm run eval:agents
npm run release:verify

协议异常时先尝试 MCP_PROTOCOL_MODE=legacy；工具选择异常时可临时使用 MCP_TOOLSET=full。只有确认 v4 兼容层无法接受时再回退 v3。

完整说明见仓库中的 docs/migration-v3-to-v4.md。
