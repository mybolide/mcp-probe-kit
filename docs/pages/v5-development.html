MCP Probe Kit 5.0.0 开发版指南

5.0.0 已在开发分支，但尚未发布至 npm / MCP Registry，也没有正式发布 Tag。

当前可公开安装的稳定版仍是 4.1.1。不要把 npm latest、npx mcp-probe-kit@5.0.0 或旧版迁移指南当作开发版的安装方式。

English: Version 5.0.0 is an unpublished source milestone. Public npm stable remains 4.1.1. Build the feature branch locally; do not assume a published 5.0.0 package exists.

1. 安装渠道 / Install the correct version

公开稳定版（旧版功能，仍可用）：

npx -y mcp-probe-kit@4.1.1 install-agent

5.0.0 源码开发版（需要 Node.js 22+ 才能启用 DevControl）：

git clone --branch feature/devcontrol-project-task-ledger https://github.com/mybolide/mcp-probe-kit.git
cd mcp-probe-kit
npm ci
npm run build

在 MCP 宿主配置中将服务器命令设为 node，参数设为实际绝对路径 /ABSOLUTE/PATH/mcp-probe-kit/build/index.js，然后重启宿主。不要把开发版源码误写成 npm 的已发布版本。

2. DevControl：管理任务，不代替 Agent / Governance, not execution

DevControl 提供项目本地 SQLite 任务账本、Web 工作台、依赖与文件范围约束、租约和真实测试门禁。Agent 负责实现、独立审查、执行业务 SQL 和真实测试；DevControl 不会代替 Agent 编码或独立审查，也不应绕过 Git Hook。

使用构建后的可执行脚本运行项目任务命令（请替换路径）：

node /ABSOLUTE/PATH/mcp-probe-kit/build/index.js devcontrol onboard --project-root /PATH/TO/PROJECT
node /ABSOLUTE/PATH/mcp-probe-kit/build/index.js devcontrol next --project-root /PATH/TO/PROJECT
node /ABSOLUTE/PATH/mcp-probe-kit/build/index.js devcontrol workspace-status --project-root /PATH/TO/PROJECT
  1. 先审核需求/设计，提出任务计划并由 Owner 明确批准。草稿不等于已获执行授权。
  2. devcontrol claim 领取有效租约，在冻结的 allowedPaths 内修改。
  3. Agent 自行实现、测试、复审，只提交获准文件；以 devcontrol complete、report 提供真实证据。
  4. devcontrol verify 真正运行规定的 Gate；只有通过才能算 Verified。范围变更须重新评审。

3. History Session、Memory 与迁移

Node.js 22+ 的 Git 项目默认将 History Session 保存于项目本地 SQLite hs_* 表；旧历史 Markdown 可以安全导入，在不支持的环境下可回退文件后端。DevControl 任务账本使用独立数据表；可选的 Qdrant Memory 是另一项跨项目服务，不能混同。

升级旧项目时先备份忽略状态和未提交的 Owner 工作，建立独立源码构建；确认正确项目根目录、历史恢复和已批准的任务门禁，绝不把迁移操作视为生产发布许可。
