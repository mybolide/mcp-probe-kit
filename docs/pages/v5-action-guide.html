Agent 怎样正确调用 74 个 DevControl action？

答案是：不需要记住 74 个动作。 一个 devcontrol MCP 工具，先通过只读 action=guide 找到当前阶段的操作，再用 SQLite 中实际冻结的任务合同执行。v4 文件式 start_* / Plan / Markdown History 不再支持。

1. 先导航，再执行 / Guide → Action

不知道下一步？用下面的 MCP 工具入参。guide 不要求项目路径，不访问任务数据库，不创建任务或审批。 通用 MCP 启动流程可能另外同步已识别项目的托管 Skill/AGENTS.md。

{"action":"guide","input":{"intent":"feature"}}

接下来按返回的阶段示例操作，只有真正写入项目时才提供目标 Git 目录：

{"action":"feature-create","project_root":"/ABSOLUTE/GIT/PROJECT","input":{"name":"login","description":"用户登录","layout":"flat"}}

错误 action 会提示调用 guide。Agent 不得猜测 Task ID、修订号、哈希、租约或 Owner 授权。

2. 九种常见意图 / Nine intents

intent你要做的事常用动作
start恢复项目、继续History bootstrap → onboard → next
feature需求→设计→任务feature-create / feature-save / feature-task-brief
planning版本计划审批plan-review / plan-propose / plan-approve
task领取一个叶子任务next / execution-contract / claim
verification真实测试与验收complete / report / gate-review / verify
bug缺陷管理work-items / bug-step-save / bug-task-link
idea新想法评审idea-capture / idea-assess / idea-review / idea-decide
scope冻结范围变更release-work-scope-* / release-work-incremental-*
architecture架构工件审批artifact-check / artifact-stage / artifact-approve

3. v5 完整执行链

  1. 恢复 SQLite History 与冻结任务，不重建已有任务。
  2. 需求：真实 FR/NFR、场景、验收条件，原文和版本留在 SQLite。
  3. 设计：接口/数据/异常/安全约束，作为开发和测试用例来源。
  4. 最小任务：父子阶段清楚，每个叶子只有一个独立验收目标，包含精确文件、依赖、正反测试、停止条件（新 Feature 叶子不超过 4 小时）。
  5. 独立复审、Owner 精确 Hash 审批：草稿显示“待审核”，但不可领取。
  6. 开发：claim 后 Agent 只改批准路径，自己编译和执行真实测试。
  7. 证据：完成报告、证据、外部 Gate 的独立 reviewer 结论，verify 不接受凭空通过。
  8. 会话交接：history_session_checkpoint 留下实际 Commit 和下一步。

4. 启动时自动检查 Skill 与 AGENTS.md

MCP 启动后先核对目标项目的 Skill、AGENTS.md 托管区及指导修订号，同为 5.0.0 但指导过期也会同步。无法定位项目时不写入 MCP 安装目录；首次显式 project_root 调用再检查。保留用户自己写的规则，重复启动不反复改写。

源码开发版并未发布 npm / MCP Registry；当前公开稳定版仍为 v4.1.1。更新源代码不等于已替换客户端运行包，更不代表正式对外发布。
